# ccxai

`plugins/ccx/bin/ccx` dispatches scoped tasks to a Grok 4.6 worker running under the Grok
Build CLI headless mode. Claude Code orchestrates, Grok executes. See `DESIGN.md` for why
the CLI and not the API (short version: only the CLI can spend a grok.com subscription, and
a worker without tools defeats the point).

## Invariants — each one is a bug that already happened

Do not "simplify" these away. Every one was found by using the tool, not by reading it.

- **The envelope is two-phase.** Phase 1 runs free-form; phase 2 `--resume`s at low effort
  purely to format. Putting `--json-schema` on the working call lets constrained decoding
  answer on turn 1 *without calling any tools* — measured at ~1 in 5, and the failure is a
  confident fabricated answer, not an obvious error. `--schema-inline` exists to reproduce
  the old behaviour; it is not the default for this reason.
- **MCP is denied on every run** (`--deny "MCPTool(*)"`). MCP servers are separate processes
  **outside** the kernel sandbox, so a "read-only" worker could still do remote writes
  through them. This is not theoretical: a read session here had `signoz_delete_alert`
  attached against a live instance.
- **The profile is pinned per invocation**, never inherited from `~/.grok/config.toml`
  (which sets `yolo = true` / `always-approve`).
- **The session UUID is generated by us and written to `meta.json` before dispatch.** A
  worker session nobody wrote down is unrecoverable work. SIGKILL is still untrappable, which
  is why the pre-dispatch write and `_reconcile` both exist.
- **The worker dies with the dispatcher.** SIGTERM/SIGINT used to be unreportable for a
  different reason than SIGKILL: bash does not service traps while a *foreground* child runs,
  so the handler fired only after the worker exited. ccx died, the worker kept running and
  kept **billing**, and `fanout` orphaned N of them at once. The dispatch is therefore
  backgrounded and `wait`ed on — that is load-bearing, not style — and fanout `pkill -P`s the
  `ccx run` inside each subshell so every child records its own `killed` run.
- **`--read` refuses a cwd on a temp path.** Every sandbox profile leaves `/tmp` writable, so
  the read-only guarantee simply does not hold there. The list must include the *unresolved*
  `/var/folders/*`, not just `/private/var/folders/*` and `$TMPDIR`: macOS names TMPDIR under
  `/var/folders`, so any context that does not export TMPDIR (cron, launchd, `env -u TMPDIR`)
  walked straight past this guard.
- **Worker output is untrusted data.** `total_cost_usd` reached `python3 -c "print(round($COST
  + $C2, 8))"` by string interpolation, so a worker that returned a string there executed code
  in the orchestrator. Arithmetic on worker-supplied values uses `awk -v` (which binds them as
  data) and jq coerces the field to a number first.
- **`set -euo pipefail` + a pipeline that legitimately fails = a silent abort.** `grep` with no
  match, `grep -c` on a zero count, and `ls` on an empty glob all exit non-zero; under pipefail
  the enclosing `var=$(...)` kills the script with no message. This produced four separate bugs
  (`doctor` dying on a normal config, `cont` exiting 2 with no output and its graceful
  unknown-session path unreachable, and `fanout` truncating its summary and total). Any such
  substitution needs `|| true` and an explicit empty check.
- **A quota/auth refusal is exit 6, not exit 5, and it arms a breaker.** An exhausted
  subscription looks exactly like a crash — grok exits non-zero with no JSON — so it used to
  surface as "worker produced no parseable JSON". An orchestrator cannot tell those apart, so
  it retries, and `fanout` dispatched every remaining brief into the same wall. A refusal now
  writes `$CCX_HOME/.quota-block`; the next `ccx run` refuses before dispatching, `fanout`
  stops and reports the briefs it skipped, and `ccx doctor` clears the block once auth answers
  normally. The block expires on its own (`CCX_BREAKER_TTL`, default 900s).
  **The detection patterns are NOT verified against a real exhausted subscription** — that
  cannot be provoked on demand. They are a broad match over stderr, applied only to a dispatch
  that already failed with no usable output, so a false positive costs one blocked run and
  expires, and a false negative just restores the old behaviour.
- **A run that ends early is still logged.** Timeout (`exit 4`) and unparseable-response
  (`exit 5`) wrote `meta.json` and then returned without appending to `runs.jsonl`, while
  `ccx stats` filters failures on exactly those statuses — so the failure report was
  structurally incapable of showing a timeout. Both paths go through `_terminal_meta`, which
  writes the full record shape and logs it.
- **The reconcile lock breaks when it is demonstrably stale.** It was released only by a
  `trap ... RETURN`, which does not run on SIGTERM, so one killed pass left the lock dir on
  disk and every later pass hit `mkdir || return 0` and gave up — crash repair silently off
  for good. A lock older than 900s is broken and retaken; a fresh one is still respected.
- **fanout attributes a worker by the run id the child printed**, never by globbing
  `runs/*-<slug>-*`. That glob matched every run that ever used the same brief name, so a
  worker that died before creating its run dir reported an *older* run's turns/cost/seconds
  and that stale cost entered the fanout total.

## Changing ccx

- **Never edit `bin/ccx` while a run is in flight.** Bash reads scripts lazily by byte
  offset; the running process resumes into rewritten content, corrupts that run, and emits
  errors that look like real syntax bugs. This wasted a debugging cycle already.
- Regression-check the guard rails after any edit — all three must fail *before* dispatch:

      ccx run --read --worktree w -- x          # profile conflict
      ccx run --worktree 'a/../../x' -- x       # path traversal
      ccx run --read --cwd /tmp -- x            # temp-path cwd
      ccx run --read --cwd "$TMPDIR" -- x       # temp-path cwd via /var/folders

- Tests must parse under **bash 3.2** — that is `/bin/bash` on macOS, and it has no
  `mapfile`/`readarray`. Check with `/bin/bash -n tests/*.sh`; the nix bash on PATH is 5.x and
  will happily accept things the system bash cannot run.
- `shellcheck -S warning` is clean except four `SC2209`s, which are false positives — it
  reads `PROFILE=read` as the `read` builtin. **shellcheck is not installed on this machine**,
  so a bare `shellcheck ... && echo clean` reports success vacuously; check the binary exists.

## Claims about grok must be tested, not read

The bundled `~/.grok/README.md` is older than the binary and wrong in places; `grok --help`
wins. The CLI auto-updates and drops flags across majors (1.0 removed `--check` and
`--best-of-n` mid-session). Docs also overstate the sandbox: "child network blocked" is
Linux/Landlock only and a **no-op on macOS** — verified with a curl canary returning 200.

Verify with a canary before documenting any safety property.

## Running the tests

```bash
for t in tests/*.sh; do [[ "$t" == */mutate.sh ]] && continue; "$t" || echo "FAILED: $t"; done
tests/mutate.sh          # slower; run it after any change to ccx or to a test
```

Nine files, 97 assertions, all using a stub `GROK_BIN` and a throwaway `CCX_HOME` —
no test dispatches a real worker or spends money.

**A test here is only finished when it fails on the bug it guards.** `tests/mutate.sh`
now enforces that instead of leaving it to discipline: it breaks one invariant at a time in a
*copy* of `ccx`, runs the test file that is supposed to notice, and fails if the mutation
survives. Add a mutation whenever you add an invariant.

This is not ceremony. The rule exists because the first `phase-parity.sh` passed against two
genuinely broken variants and hid containment bugs for several commits. The harness earned
itself on its first run: `--permission-mode acceptEdits` — the exact regression documented
above as costing a debugging cycle — survived the **entire** suite, because no test had ever
asserted that flag's value.
